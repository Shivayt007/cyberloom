# Cyberloom Link Inspector

Simple mobile-friendly website: paste a Cyberloom short URL, observe the countdown/redirect stages, see live terminal messages, and collect candidate links from the verified MessyCloud destination. It does **not** download files or bypass CAPTCHA / access controls. It may not work if the shortener changes its flow or blocks automated browsers.

## EasyPanel deployment

1. Create a new **Project** and **App Service** in EasyPanel.
2. Source: **GitHub**, repository `Shivayt007/cyberloom`, branch `main`.
3. Build: **Dockerfile** (path: `Dockerfile`, build context `/`).
4. Environment variables: `APP_PASSWORD=<your unique long random password>`; optionally copy `ALLOWED_START_HOSTS` and `TARGET_HOSTS` from `.env.example`.
5. Expose **port 8000** as HTTP and assign an EasyPanel domain with HTTPS.
6. Deploy. Visit the domain, enter password and Cyberloom URL, click **Inspect Link**. Health endpoint: `/health`.

Use a strong password; do not disable authentication or publicly expose the browser to arbitrary URLs. The server limits input hosts and blocks private IPs as defense in depth, but networking restrictions are recommended. The Playwright browser runs as an unprivileged user; production browser hardening and container isolation remain your responsibility. The built-in image is large (~gigabytes) because it contains browsers.

**No EasyPanel auto-deployment is configured.** If your EasyPanel service enables auto-deploy on push, future updates can trigger that; otherwise click Deploy manually.

## Local development (desktop Linux/Windows, not Android)

```sh
pip install -r requirements.txt
python -m playwright install chromium
export APP_PASSWORD='set-a-long-random-password' # Windows PowerShell: $env:APP_PASSWORD='...'
uvicorn app:app --host 127.0.0.1 --port 8000
```

## API

`POST /api/inspect` with header `X-API-Key: <APP_PASSWORD>` and JSON `{"url":"https://www.cyberloom.best/l/abc123","timeout":120,"settle":12}` streams newline-separated JSON events. Only one scan runs at a time per instance. No links are retained on server after completion.

## Notes

- No automatic CAPTCHA bypass or timer skipping. Countdown pages are allowed to run naturally.
- Some links inside frames or generated by network scripts may not be found.
- The external site's policies and your rights to access links still apply.

## When Stackmint requires human verification

Cyberloom may redirect to `stackmint.ink`, which can display an **I'm human** challenge. Headless Chromium cannot reliably pass this verification. The website now detects a visible verification prompt and stops early, showing an **Open Stackmint in my browser** link instead of waiting 120 seconds.

To continue, open the link in your normal browser, complete the human-verification step yourself, click **Continue to Destination**, then copy the final `messycloud.ink` URL into the inspector's input field and run again. The inspector also accepts permitted MessyCloud destination URLs directly. This process does not transfer browser cookies or verification state from your mobile browser to the VPS, and destination pages that require those may remain inaccessible to the headless browser. The app does not bypass access controls or CAPTCHAs.

## Redirect chains captured in the 2026-10-23 walkthrough

A phone recording showed LinkVoyage's "Continue to Destination" page, transient Indiatimes pages, a second MessyCloud "Continue to Destination" page, and finally a MessyCloud file page showing an **M1 DIRECT** server option. Those intermediate domains may change. The automation now reports all open tabs, only clicks Continue on known redirect hosts (Cyberloom, Stackmint, LinkVoyage, and MessyCloud), and does **not** stop merely because MessyCloud's hostname appears: it waits for the actual file page. It never attempts to defeat a CAPTCHA. Server buttons implemented solely through JavaScript may need an additional, site-specific extractor.
